# Requirements Archive — claude-code-tray v1.6 (TUI Polish)

**Status:** ✅ SHIPPED 2026-07-24 — 5/5 requirements delivered.

Milestone goal: turn the functional v1.5 Textual dashboard into a btop-inspired
terminal surface while preserving its existing daemon snapshot, polling model,
and `claude_monitor.core` formatting boundary.

## v1.6 Requirements

### TUI (terminal rendering polish)

- [x] **TUI-06:** Usage percentage, burn rate, and reset countdown use
  green/yellow/red proximity colors for both quota caps. — **Validated**
- [x] **TUI-07:** Both quota caps render as gradient progress-bar gauges rather
  than plain percentage rows. — **Validated**
- [x] **TUI-08:** The trends panel renders a taller, colored graph decoded from
  core's existing sparkline data without introducing new trend math. —
  **Validated**
- [x] **TUI-09:** The live sessions table uses status-colored, striped rows with
  improved spacing. — **Validated**
- [x] **TUI-10:** Usage, trends, and sessions appear in titled, rounded bordered
  panels. — **Validated**

## Delivered Beyond Planned Requirements

- Quota projection or exhaustion ETA beside each cap gauge.
- Mon-Sun hourly usage heatmap using dashboard-parity normalization.
- Focus action for the selected live session, reusing the existing daemon/tmux
  path.
- Selection retention across automatic table refreshes.
- Background-work resilience on client disconnect.
- Clock-hour trend bars based on trustworthy usage increments.

## Deferred

- Standalone no-daemon mode reading `usage-history.jsonl` directly.
- TUI-side mutation of daemon state such as mute or configuration changes.
- A Rust TUI rewrite; the shipped Python Textual implementation remains its
  behavioral and visual reference.

## Out of Scope

- New polling, a second data source, or a new snapshot verb.
- A new runtime dependency beyond the already-scoped `textual` extra.
- Replacing the rendering layer with `curses`.
- Wayland support.
