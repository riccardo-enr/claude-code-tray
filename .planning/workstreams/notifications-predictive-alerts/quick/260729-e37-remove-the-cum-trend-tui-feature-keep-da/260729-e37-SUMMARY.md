# Quick Task 260729-e37: Remove the cum_trend TUI feature, keep dashboard-only reservation Summary

Removed the cum_trend (cumulative-window-usage sparkline) feature entirely from the Rust TUI, the daemon's wire-protocol plumbing in `claude-monitor.py`, and the shared fixture corpus -- the feature was added across four prior quick tasks (260727-krn/lns/mki/nlo) but the user decided it should be dashboard-only, never shown in the TUI. `claude_monitor.core.build_cum_trend` / `cum_trend_axis` and their existing unit tests are completely untouched, reserved for a future dashboard feature.

## What Was Built

- **Task 1 (fixture corpus):** `fixtures/generate.py` no longer defines `cum_trend`/`cum_trend_axis` wire or expect keys anywhere. Deleted the `cum-trend-populated` and `cum-trend-clipped-keeps-newest` fixture entries plus their `_CUM_CLIMB`/`_CUM_FUTURE_BLANK`/`_CUM_SPARKLINE` helper constants. Regenerated `fixtures/snapshot/*.json` (24 fixtures, matching the corpus-count assertion's `>= 15` floor) and `git rm`'d the two now-orphaned JSON files the generator doesn't delete on its own. `fixtures/README.md`'s Expectations table dropped the `cum_trend`/`cum_trend_axis` rows.
- **Task 2 (Rust crate):** `rust/src/snapshot.rs` dropped the `cum_trend`/`cum_trend_axis` `Snapshot` fields, their wire-contract doc comment lines, and their `from_value` normalization calls -- `normalize_trends`/`normalize_trend_axis` themselves are untouched, still serving `trends`/`trend_axis`. `rust/src/main.rs` removed `snapshot_cum_trend`, `clip_to_newest`, the second-graph block in `draw_trends` and `trends_panel_height`, and the now-dead test helpers `buffer_text`/`render_trends_rows`. Three cum-specific tests were deleted outright; the fourth (`cum_trend_absent_is_a_true_no_op_on_render_and_layout`, the only assertion pinning the pre-cum height formula) was folded into a new `trends_panel_height_matches_the_bar_chart_plus_border_formula` test. `rust/tests/fixtures.rs` dropped the `cum_trend`/`cum_trend_axis` match arms in `check()` and the now-dead `check_axis` helper.
- **Task 3 (Python daemon):** `claude-monitor.py`'s `Monitor.__init__` and `compute_trends` no longer cache or compute `cum_trend`/`cum_trend_axis`; `_handle_conn`'s socket snapshot dict no longer carries those two keys. `claude_monitor/test_claude_monitor.py`'s IN-01 socket-wire test shrank `_FakeMonitor`'s fields and the key-set/value assertions to match. The `build_cum_trend`/`cum_trend_axis`/`CUM_TREND_INTERVAL` imports and the pure-function unit tests (lines ~620-664, testing `core.py`'s retained functions directly) are byte-for-byte unchanged.

### Deferred: Task 3 steps 10-12 (deploy: `just install` / `just restart` / `just status`)

**Found during:** Task 3, before running the deploy steps.

**Issue:** This execution runs inside a Claude Code git worktree
(`/home/riccardo/code/claude/claude-code-tray/.claude/worktrees/agent-a83be7d7e3cd81688`),
a separate working directory on its own branch, cleaned up after the wave
merges. The justfile's `entry` variable and `install.sh`'s `SRC` both resolve
relative to the invoking checkout:

- `just selfcheck` runs `python3 ~/.claude/hooks/claude-monitor.py --selfcheck`
  -- that path is a symlink into the **main repo checkout**
  (`/home/riccardo/code/claude/claude-code-tray/claude-monitor.py`), not this
  worktree's edited file. Running it as written would silently verify the
  wrong tree (the pre-change main-branch code), giving a false-green result.
- `just install` runs `./install.sh`, which does
  `ln -sf "$SRC/claude-monitor.py" "$HOOKS/claude-monitor.py"` with
  `SRC="$(cd "$(dirname "$0")" && pwd)"` -- run from this worktree, that
  **repoints the user's live deployed symlink at the ephemeral worktree
  path**, and copies a `claude-tui` binary built from the worktree's `rust/`
  source into `~/.local/bin`. The worktree directory is deleted once this
  wave's branch merges, which would leave the symlink dangling and kill the
  live tray daemon.
- `just restart` relaunches the daemon via that same `entry` symlink -- same
  worktree-vs-main-checkout mismatch.

**Substitution:** Verified all four gates directly against this worktree's
own files instead: `python3 ./claude-monitor.py --selfcheck` (imports the
worktree's own `claude_monitor` package via `sys.path[0]`), plus
`cargo test`, `cargo clippy --all-targets -- -D warnings`, and
`ruff check .`, all run from the worktree root. All four are green/clean,
proving the code change itself is correct.

**Remediation (for the user / orchestrator, after this branch merges to
main):** from `/home/riccardo/code/claude/claude-code-tray` (the main
checkout, not a worktree), run:

```
just install && just restart && just status
```

This rebuilds and installs the `claude-tui` binary from the merged source and
relaunches the Python daemon so the running system reflects the change --
`just install`/`just restart` were not run as part of this quick task.
