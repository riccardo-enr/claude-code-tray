# Phase 11 — UI Design Contract

> Rendering-state contract for the Rust client foundation. Generated by
> gsd-ui-researcher for downstream planning, execution, and UI verification.

---

## Phase Boundary

Phase 11 does not ship a new visual surface. It defines the safe, deterministic
state that Phase 12 may render and that Phase 13 may transition between.

In scope:

- independent availability for `usage`, `trends`, `heatmap`, and `sessions`;
- stable nonfatal failure categories with safe structured context;
- display-safe, length-bounded session text;
- separate opaque focus-routing values that are never rendered;
- deterministic fixtures for accepted, partial, rejected, and hostile inputs.

Out of scope:

- panel layout, responsive allocation, gauges, graphs, heatmap, borders, colors,
  typography, and empty-state presentation (Phase 12);
- refresh behavior, navigation, selection, focus feedback, cold-start/outage
  presentation, retry behavior, and human-facing error wording (Phase 13);
- Python-versus-Rust visual parity approval and installation cutover (Phase 14).

No Phase 11 task may add a placeholder TUI, choose replacement visuals, or
introduce user-facing copy merely to exercise the client. Tests consume the
normalized rendering state directly.

## Rendering-State Contract

### State ownership

| State surface | Required normalized state | Renderer guarantee |
|---------------|---------------------------|--------------------|
| Fetch result | `accepted(snapshot)` or one fetch failure | A rejected fetch supplies no partial root and cannot mutate the last accepted snapshot |
| Snapshot section | `available(value)` or `unavailable(section.schema)` independently for `usage`, `trends`, `heatmap`, and `sessions` | One malformed section cannot blank valid siblings |
| Sessions collection | ordered valid entries plus `rejected_entry_count` | A malformed entry cannot create a row or remove valid peers |
| Display string | sanitized, bounded printable Unicode | Renderer never receives raw terminal-control bytes or markup instructions |
| Focus routing | bounded, validated opaque values separate from display strings | Routing values are never rendered, logged verbatim, or substituted with truncated display text |
| Focus action | success or an action-scoped focus failure | Focus failure cannot mark snapshot state stale or alter refresh state |
| Rendering boundary | success or `render.failed` | Rendering failure is nonfatal and does not expose an implementation traceback |

An accepted root object always yields all four section-state slots, even when one
or more slots are unavailable. Missing optional fields are explicit absence.
Missing required fields invalidate only the narrowest owning section or session
entry. Unknown fields are ignored. Wrong types are never coerced.

### Stable failure categories

The public state model must expose these stable semantic codes (enum names may
follow Rust conventions, but serialized fixture codes are fixed):

| Code | Meaning | Safe context allowed |
|------|---------|----------------------|
| `snapshot.transport` | Socket creation, connection, send, or receive failed | operation only |
| `snapshot.timeout` | Whole snapshot operation exceeded its deadline | deadline milliseconds |
| `snapshot.framing` | Missing/invalid line framing or trailing framed content | framing reason only |
| `snapshot.too_large` | Response exceeded the 1 MiB cap | configured cap |
| `snapshot.decode` | Bytes are not valid UTF-8 or JSON is malformed/truncated | input kind and byte offset when available |
| `snapshot.root_schema` | Decoded root is not an object | observed JSON kind |
| `section.schema` | One decoded section failed normalization | section name and field path only |
| `render.failed` | A renderer rejected otherwise normalized state | renderer operation only |
| `focus.invalid_target` | Opaque target fields fail type/bounds/action requirements | field name only |
| `focus.transport` | Focus request could not be sent | operation only |
| `focus.timeout` | Focus request exceeded its deadline | deadline milliseconds |

Safe context must be finite, typed, and allowlisted. It must never contain raw
payload text, a raw filesystem path, session title, tmux value, pane value,
terminal control characters, or an implementation-specific error/debug chain.

### Last-good-state handoff

- Normalization is pure: input bytes plus an injected clock produce one result.
- A rejected fetch returns only its failure; it never returns a half-updated
  snapshot and never mutates a prior snapshot.
- The client API accepts no mutable last-good snapshot. The Phase 13 state
  machine owns whether a prior accepted value is preserved or presented.
- A section-level schema failure lives inside an accepted snapshot and is not a
  transport/outage signal.
- A focus result is action-scoped and cannot modify snapshot freshness.

## Untrusted Text Contract

Sanitization occurs once at the normalization trust boundary for every
daemon-sourced display string.

| Input class | Required output |
|-------------|-----------------|
| Complete ANSI CSI sequence | one visible `U+FFFD` replacement marker |
| Complete ANSI OSC sequence, terminated by BEL or ST | one visible `U+FFFD` replacement marker |
| Other complete ESC/C1 control sequence | one visible `U+FFFD` replacement marker |
| Lone/incomplete escape sequence | one visible `U+FFFD` replacement marker |
| Remaining C0/C1 control, including tab/newline/carriage return | one `U+FFFD` marker per control character |
| Invalid UTF-8 | reject the fetch as `snapshot.decode`; do not lossy-decode wire bytes |
| Printable Unicode | preserve literally |
| Markup-looking printable text such as `[bold]repo[/]` | preserve literally; renderer must use non-markup APIs |
| Display value over 256 Unicode scalar values | preserve the first 255 scalars and append `…` |

The 256-scalar display bound is independent of layout truncation. Phase 12 may
clip or ellipsize further to fit a terminal, but it must not recover or display
discarded raw text.

Opaque focus-routing fields are type-validated UTF-8 strings capped at 4096
bytes each. They are never sanitized into display strings, never truncated into
a different routing target, and never included in diagnostics. A value beyond
the routing cap yields `focus.invalid_target`.

Renderers must use plain/non-markup text APIs even for already sanitized values.
Sanitization removes terminal controls; it intentionally does not alter
printable markup-looking content.

## Fixture and Verification Contract

The language-neutral fixture corpus pairs raw wire input with expected semantic
state or a stable error code. Canonical fixtures are hand-authored and contain
no machine-specific paths, private usage values, live timestamps, or daemon
dependency.

Mandatory fixture coverage:

| Case | Required assertion |
|------|--------------------|
| Full valid snapshot | all four sections available with exact normalized values |
| Missing optional fields | explicit absence without section rejection |
| Malformed sibling section | that section unavailable; valid siblings unchanged |
| Mixed valid/malformed sessions | valid entries preserved in daemon order; deterministic rejected count |
| Unknown fields | ignored with no semantic output change |
| Wrong JSON types | no coercion; narrowest section or entry rejected |
| Malformed/truncated JSON | `snapshot.decode` and no accepted snapshot |
| Non-object root | `snapshot.root_schema` |
| Invalid UTF-8 | `snapshot.decode`, never U+FFFD wire decoding |
| Oversized response | `snapshot.too_large` at the 1 MiB boundary |
| ANSI CSI/OSC and remaining controls | exact one-marker-per-sequence/control normalized display value |
| Printable markup-like text | exact literal value survives normalization |
| Overlong display value | exact 255-scalar prefix plus `…` |
| Valid focus target | exact existing focus request shape is emitted |
| Invalid/overlong focus target | `focus.invalid_target`; no request is sent |
| Render failure seam | `render.failed` is nonfatal and contains no raw/debug text |

Golden assertions compare semantic values, section availability, rejected-entry
counts, safe display strings, and stable codes under a frozen clock. They do not
compare map iteration order, debug wording, Rust enum debug output, memory
layout, or implementation-specific serialization.

## UI Considerations

> Phase 11 has no widgets. These rows cover the normalized state surfaces that
> later renderers consume and are resolved by deterministic fixture evidence.

0 unresolved.

| empty | sessions collection | ✅ covered | Empty valid sessions normalize as `available([])`, distinct from an unavailable section; Phase 12 owns the copy |
| loading | snapshot state | dismissed | In-flight/loading presentation belongs to the Phase 13 event loop; Phase 11 exposes only completed outcomes |
| error | fetch, section, render, and focus results | ✅ covered | Stable typed codes and safe allowlisted context represent failures without raw text or tracebacks |
| populated | normalized snapshot and sessions | ✅ covered | Full-valid fixtures assert all sections and preserve daemon session order |
| partial | independently normalized sections and entries | ✅ covered | Malformed sections become unavailable independently; malformed sessions increment the rejected count without blanking peers |
