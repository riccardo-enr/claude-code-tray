<assumptions>
Surfaced from the deterministic edge probe (no SPEC.md exists for this phase).
Both are planner judgement calls that CONTEXT.md and 11-UI-SPEC.md imply but do
not state in so many words. If either is wrong, say so before execution.

1. **A JSON `null` in the `usage`, `trends`, or `heatmap` slot is a semantic
   value, not a schema failure.** The daemon initializes `mon.usage`,
   `mon.trends` and `mon.heatmap` to `None` and legitimately serves `null` before
   its first successful poll (`claude-monitor.py:65-68`), and `claude-tui.py`
   renders that as its own "unavailable" row rather than treating it as
   corruption. So `usage: null` normalizes to `Available(None)` -- the section
   was present and well-formed, it simply carries no value -- and is distinct
   from `Unavailable(section.schema)`, which means the section was present and
   malformed. This is the direct reading of D-04 and of the 11-PATTERNS.md note
   that "None/empty is a semantic value only where the daemon contract allows it;
   it must not double as schema failure".

2. **No Unicode normalization (NFC/NFD/NFKC/NFKD) is applied to any daemon
   string, and equality is exact scalar-sequence equality.** 11-UI-SPEC.md fixes
   the display bound at 256 Unicode *scalar values* and the routing bound at 4096
   *bytes* -- two deliberately different units -- but is silent on normal forms.
   D-11 requires printable Unicode to be preserved *literally*, which a
   normalization pass would violate. Truncation therefore counts `char`s, routing
   caps count UTF-8 bytes, and no normalization crate is added.
</assumptions>

**`src/lib.rs`.** Declare `pub mod client; pub mod error; pub mod model; pub mod

attributes `#![forbid(unsafe_code)]` and a `#![cfg_attr(not(test), deny(...))]`
block denying `clippy::unwrap_used`, `clippy::expect_used`, `clippy::panic`,

**`src/error.rs` -- data only, no I/O, no construction logic.** Define four
public failure types plus their context enums, matching the fixed serialized
codes in 11-UI-SPEC.md exactly:

`SnapshotFailure` with variants `Transport { op: TransportOp }`,
`Timeout { deadline_ms: u64 }`, `Framing { reason: FramingReason }`,
`TooLarge { cap_bytes: usize }`,
`Decode { kind: DecodeKind, offset: Option<usize> }`, and
`RootSchema { observed: JsonKind }`. Its `code()` returns `"snapshot.transport"`,
`"snapshot.timeout"`, `"snapshot.framing"`, `"snapshot.too_large"`,
`"snapshot.decode"`, `"snapshot.root_schema"` respectively.

`SectionFailure { section: SectionName, field_path: &'static str }` with
`code()` returning `"section.schema"`.

`FocusFailure` with variants `InvalidTarget { field: FocusField }`,
`Transport { op: TransportOp }`, `Timeout { deadline_ms: u64 }`, whose `code()`
returns `"focus.invalid_target"`, `"focus.transport"`, `"focus.timeout"`.

`RenderFailure { op: RenderOp }` with `code()` returning `"render.failed"`.

Context enums: `TransportOp` (`Socket`, `Connect`, `Send`, `Receive`),
`FramingReason` (`MissingNewline`, `TrailingContent`, `EmptyResponse`),
`DecodeKind` (`Utf8`, `Json`), `JsonKind` (`Null`, `Bool`, `Number`, `Str`,
`Array`), `SectionName` (`Usage`, `Trends`, `Heatmap`, `Sessions`),
`FocusField` (`Pane`, `Tmux`, `Title`, `Term`), `RenderOp`.

The allowlist is enforced **structurally**: every context field is a fieldless
enum, an integer, or a `&'static str`. That makes it impossible for
wire-derived text to be stored in an error, because an owned heap string is not
a permitted field type in this module. Give each enum a `label()` returning a
lowercase `&'static str` for fixture comparison (`"connect"`, `"utf8"`,
`"missing_newline"`, `"usage"`, and so on). Derive `Debug`, `Clone`, `PartialEq`,
`Eq` on every type here; that is safe precisely because no field can carry
payload text. Do not implement `std::error::Error` conversions from
`std::io::Error` or `serde_json::Error` that retain the source -- map them at
the call site into the fieldless variants instead, so no OS or library string is
ever retained.

**`src/model.rs`.** Define `SectionState<T>` as `Available(T)` or
`Unavailable(SectionFailure)`, with helpers `as_available(&self) -> Option<&T>`
and `failure(&self) -> Option<&SectionFailure>`.

Define `Snapshot { received_at: f64, usage: SectionState<Option<Usage>>, trends:
SectionState<Option<Vec<DisplayText>>>, heatmap: SectionState<Option<Heatmap>>,
sessions: SectionState<Sessions> }`. The inner `Option` on the first three slots
is load-bearing: it encodes the daemon's legitimate `null` (see
`<assumptions>` item 1) as `Available(None)`, distinct from
`Unavailable(SectionFailure)`.

Define `Usage` with `used_percentage: f64`, `resets_at_epoch: f64`,
`burn_rate_per_min: f64` (required) and `tokens_used: Option<f64>`,
`token_limit: Option<f64>`, `seven_day_pct: Option<f64>`,
`seven_day_reset: Option<f64>` (optional -- the daemon serves these as null under
`--api` and on older CLIs).

Define `Heatmap { grid: Vec<Vec<Option<f64>>> }` holding exactly 7 rows of 24.
Define `Sessions { entries: Vec<Session>, rejected_entry_count: usize }`.
Define `Session { id: DisplayText, dir: DisplayText, status: DisplayText,
entered: Option<f64>, frozen: Option<f64>, route: RawRoute }`.

Define `RawRoute { pane: RouteValue, tmux: RouteValue, title: RouteValue, term:
RouteValue }` -- the untruncated, unsanitized routing values, kept deliberately
separate from the display fields per D-12. `route.title` carries the raw `dir`
value while `Session.dir` carries the sanitized, bounded one; these are two
different values from the same wire field and must not be unified.

Define two newtypes with **private** inner fields:
`DisplayText(String)` -- constructible only from within `sanitize`, exposing
`as_str()`. Because the field is private and the module exports no `From<String>`
or public constructor, an unsanitized daemon string cannot be turned into a
renderable value from outside `sanitize`. That is the type-level half of D-09.
`RouteValue(String)` -- exposing `as_str()` and a `len_bytes()`. Implement
`Debug` **manually** to emit a fixed redaction placeholder rather than the value,
so a routing value can never reach a log line or a panic message verbatim (D-12).
Do not derive `Debug` on `RouteValue` or on `RawRoute`.

Define `FocusTarget` holding four validated `RouteValue`s, plus
`FocusTarget::from_session(&Session) -> Result<FocusTarget, FocusFailure>`. That
constructor is where the routing rules live, and in this task it must implement
them fully because it is the only gate between a session and the wire: each of
the four values must be at most `MAX_ROUTE_BYTES` (else
`InvalidTarget { field }` naming the offending field), and a target whose `pane`
is empty while `term` is not `"zed"` is `InvalidTarget { field: Pane }` --
copying the focusability rule at `claude_monitor/core.py:881` verbatim. Because
`request_focus` accepts only an already-constructed `FocusTarget`, an invalid
target provably opens no connection and sends no bytes.

**`src/sanitize.rs`.** Define `DISPLAY_MAX_SCALARS: usize = 256`, `REPLACEMENT:
char = '\u{FFFD}'`, `TRUNCATION_MARKER: char = '\u{2026}'`. Write both code
points as Rust `\u{...}` escapes, never as literal glyphs, so the source stays
ASCII per the project convention while the UI-SPEC's exact code points are still
what lands in the string.

Implement `sanitize_display(raw: &str) -> DisplayText`. In this tracer the
implementation may handle only the two classes the full-valid fixture exercises
-- printable Unicode preserved literally, and a bare C0 control replaced by one
`REPLACEMENT` -- but the signature, the constants, and the sanitize-then-truncate
ordering must be final. The truncation step is part of the tracer: if the
sanitized result exceeds `DISPLAY_MAX_SCALARS` scalars, keep the first 255 and
append `TRUNCATION_MARKER`, counting `char`s not bytes. Truncation must run
**after** sanitization, never before, or a cut could split an escape sequence.
Leave a `ponytail:` comment marking the escape-sequence recognition as Plan
11-03's work so the gap is explicit rather than silent.

**`src/normalize.rs`.** Implement `normalize_snapshot(bytes: &[u8], now_epoch:
f64) -> Result<Snapshot, SnapshotFailure>` as a pure function -- no clock read,
no environment read, no I/O. Order of operations: `std::str::from_utf8` first,
mapping failure to `Decode { kind: Utf8, offset: Some(e.valid_up_to()) }` and
never lossy-decoding; then `serde_json::from_str::<serde_json::Value>`, mapping
failure to `Decode { kind: Json, offset: Some(e.column()) }`; then require
`Value::Object` at the root, else `RootSchema { observed }` naming the observed
kind. Only after the root is accepted, normalize the four sections
independently. Store `now_epoch` on `received_at`.

Parse `Value` by hand -- do not add `serde` derive. Hand-walking is what makes
D-04's rules expressible: a missing key and a `null` are explicit absence, a
present key of the wrong JSON type is a rejection rather than a coercion, and
unknown keys are ignored. A derived `Deserialize` would fail the whole object and
collapse section independence.

In this tracer the four section normalizers need only cover the well-formed
shapes the full-valid fixture contains; their signatures and their independence
(each returns its own `SectionState`, none can abort a sibling) are final and
Plan 11-03 fills the rejection paths. Every daemon-sourced display string --
session `id`, `dir`, `status`, and each `trends` row -- must already go through
`sanitize_display` here, because normalization is the trust boundary (D-09).

**`src/client.rs`.** Define `SOCK_FILE: &str = "claude-monitor.sock"`,
`MAX_RESPONSE_BYTES: usize = 1 << 20`, `OP_TIMEOUT: Duration =
Duration::from_millis(1500)`, `MAX_ROUTE_BYTES: usize = 4096`, and
`SNAPSHOT_REQUEST: &[u8]` holding the request line byte-identical to the one
`claude_monitor/core.py:856` sends -- including the space after the colon, since
that is the shipped bytes. Define `socket_path() -> PathBuf` joining
`$XDG_RUNTIME_DIR` (falling back to `/tmp`) with `SOCK_FILE`, restating
`claude_monitor/core.py:799`.

Split the protocol the same way the Python does, and for the same stated reason:
`read_framed(stream: &mut impl Read, deadline: Instant, cap: usize) ->
Result<Vec<u8>, SnapshotFailure>` and `exchange_snapshot(stream: &mut UnixStream,
deadline: Instant, now_epoch: f64) -> Result<Snapshot, SnapshotFailure>` operate
on an ALREADY-CONNECTED stream and neither connect nor close -- that is precisely
what lets the tests drive them over `UnixStream::pair()` with no daemon, mirroring
the rationale in `read_line`'s docstring. `fetch_snapshot(path: &Path, timeout:
Duration, now_epoch: f64) -> Result<Snapshot, SnapshotFailure>` is the thin
connecting wrapper.

In this tracer `read_framed` must already implement the bounded whole-operation
loop: a 64 KiB read buffer, a `deadline` checked before every read, the `cap`
enforced on the accumulated length, and a stop at the first `\n`. Wire the
timeout and cap breaches to `Timeout { deadline_ms }` and
`TooLarge { cap_bytes }` now -- Plan 11-02 hardens the remaining framing and
transport cases and adds the adversarial tests. `exchange_snapshot` writes
`SNAPSHOT_REQUEST`, flushes, calls `read_framed`, and hands the bytes to
`normalize_snapshot` unchanged; it assembles no partial state of its own and
accepts no previous snapshot to merge into (D-01, D-06).

Also define `focus_message(target: &FocusTarget) -> Vec<u8>` producing the
newline-terminated JSON object with exactly the keys `action` (value `"focus"`),
`pane`, `tmux`, `title`, `term` -- the shape at `claude_monitor/core.py:884`,
which `claude-monitor.py:610-620` reads. Define `send_focus(stream, deadline,
target) -> Result<(), FocusFailure>` and `request_focus(path, timeout, target)
-> Result<(), FocusFailure>`. Plan 11-02 adds the focus tests; the signatures

<threat_model>
ASVS Level 1. Blocking severity: `high`. Every `high` threat below must be
mitigated before this plan is considered complete.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| daemon unix socket -> Rust client | Untrusted response bytes cross here. The daemon is trusted as a *process*, but the content it relays is not: session `dir` values are filesystem paths from arbitrary cloned repositories, and `tmux`/`term` values derive from terminal and window titles an attacker can influence. |
| normalized display text -> terminal emulator | Any byte that survives normalization is written to a real terminal by Phase 12. Control bytes here are code execution primitives for the emulator, not data. |
| focus routing values -> daemon `focus` action | Values the client forwards back reach `mon.focus(...)`, which shells out to tmux and wmctrl. |
| crates.io -> build | Dependency source code enters the build. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-11-01 | Tampering | `sanitize::sanitize_display` -> terminal | high | mitigate | Every daemon-sourced display string is sanitized at the normalization boundary, and `DisplayText`'s private inner field makes an unsanitized string unconstructible outside `sanitize`.
