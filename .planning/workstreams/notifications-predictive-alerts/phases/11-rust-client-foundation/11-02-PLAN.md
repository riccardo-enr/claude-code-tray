  <action>
Complete `read_framed`, `exchange_snapshot`, and `fetch_snapshot` so every path
out of them is a typed `SnapshotFailure`, then create the `socket_client`
integration test target driving each case over `UnixStream::pair()`.

**Framing rules in `read_framed`.** The loop reads into a 64 KiB buffer,
appending to an accumulator, and stops at the first `\n`. Three framing outcomes
must be distinguished rather than collapsed:
- the peer reached EOF with an empty accumulator -> `Framing { reason: EmptyResponse }`;
- the peer reached EOF with a non-empty accumulator that does not end in `\n` -> `Framing { reason: MissingNewline }`;
- the accumulator contains a `\n` at any index other than the final one -> `Framing { reason: TrailingContent }`.
This last check is deliberately cheap and deliberately partial: a second framed
object that arrives in the same read is caught, one that arrives in a later
packet is never read at all because the loop stops at the first newline. State
that limit in a `ponytail:` comment naming the ceiling -- detecting a
later-arriving second line would require a peek and buys nothing against a
single-response protocol. `claude_monitor/core.py:809-835` does not detect it
either.

**Deadline discipline.** `read_framed` takes an `Instant` deadline and checks it
BEFORE every read, returning `Timeout { deadline_ms }` where `deadline_ms` is the
configured whole-operation budget in milliseconds -- not the elapsed time, which
would vary run to run and make a fixture nondeterministic. Also call
`set_read_timeout` on the stream with the remaining budget before each read so a
peer that goes completely silent cannot park the thread past the deadline; a
`WouldBlock`/`TimedOut` io error from that per-read timeout maps to `Timeout`,
not to `Transport`.

**Size cap.** Enforce `MAX_RESPONSE_BYTES` against the accumulated length after
each read, using a checked or saturating comparison, and return
`TooLarge { cap_bytes: MAX_RESPONSE_BYTES }`. The boundary must be exclusive in
the same direction as `claude_monitor/core.py:833`: a buffer of exactly
`MAX_RESPONSE_BYTES` is accepted and only a longer one trips. Pre-size the
accumulator with a small initial capacity and never with the cap, so a hostile
peer cannot make the client allocate a megabyte by connecting.

**Transport mapping.** Map `std::io::Error` at each call site into the fieldless
`TransportOp` that names the operation -- `Socket` for socket creation, `Connect`
for `UnixStream::connect`, `Send` for the request write and flush, `Receive` for
a read error that is not a timeout. Discard the `io::Error` itself; do not retain
it, its `kind()`, or its message, because the platform message can contain the
socket path (T-11-05).

**Connect deadline ceiling.** `std::os::unix::net::UnixStream` has no
`connect_timeout`, so a connect against a listener with a saturated backlog can
block. Set the read and write timeouts immediately after connect and check the
whole-operation deadline right after connect returns, so an over-budget connect
still reports `Timeout` rather than silently consuming the budget. Mark the
residual blocking window with a `ponytail:` comment naming the ceiling and the
upgrade path (a non-blocking connect plus poll, if a real hang is ever observed)
-- the peer here is the user's own daemon on a 0700 runtime directory, so this is
a bounded, documented gap rather than an unhandled one.

**Recursion.** Do not add a recursion guard of your own: `serde_json` enforces a
128-level nesting limit during deserialization and returns an `Error`, which
already maps to `Decode { kind: Json, .. }`. Add the 512-level test to prove it
and note in a codedoc block that the depth defence is the dependency's, not
hand-rolled.

**`tests/socket_client.rs`.** Create the integration target. Give it a small
local helper that spawns a thread with one half of a `UnixStream::pair()`,
running a caller-supplied closure as the fake daemon, and returns the client
half -- this is the Rust form of the socketpair strategy at
`claude_monitor/test_claude_monitor.py:691-831` and is what makes the whole suite
daemon-free. Add one test per case in `<behavior>`. Assert on `code()` and on the
context values (`deadline_ms`, `cap_bytes`, `kind`, `observed`, `reason`), never
on `Debug` output or on human wording -- D-16 forbids locking debug wording, and
Plan 11-04's fixtures depend on the same discipline. Every test must join its
server thread so a hung server surfaces as a test failure rather than a leaked
thread.

For the oversized and exact-cap cases, generate the bytes in the test rather than
committing a 1 MiB file to git.

the two concurrency edges the deterministic probe raised for RTUI-03 and RTUI-12.

**`focus_message`.** Serialize exactly five keys: `action` fixed to `"focus"`,
then `pane`, `tmux`, `title`, `term` carrying the raw `RouteValue` strings, and
terminate with a newline. The daemon reads `msg.get("pane")`, `msg.get("tmux")`,
`msg.get("title")`, `msg.get("term")` and passes them positionally to

happens here, matching `claude_monitor/core.py:876`, and is NOT a protocol
change.

writes the message and flushes over an already-connected stream; `request_focus(path,
timeout, target)` connects, calls `send_focus`, and closes. Map io errors to
`FocusFailure::Transport { op }` and a deadline breach to
`FocusFailure::Timeout { deadline_ms }`. Both take an already-validated
`&FocusTarget`, so there is no validation branch inside them and no way to reach
the socket with an invalid target. Do not read a response: the shipped daemon
sends none, and waiting for one would be a protocol change.

Neither function may touch, accept, or return a `Snapshot`. That is what makes
D-07 structurally true rather than a convention: a focus result cannot mark
snapshot data stale because a focus function has no snapshot to mark.

**Route value bounds.** Confirm `FocusTarget::from_session` enforces
`MAX_ROUTE_BYTES` as a UTF-8 BYTE count (not a scalar count) on each of the four

per the `<assumptions>` block in Plan 11-01. Over-bound yields
`InvalidTarget { field }` naming which of the four failed.

<threat_model>
ASVS Level 1. Blocking severity: `high`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| daemon unix socket -> `client::read_framed` | Untrusted response bytes, arbitrary length, arbitrary timing, arbitrary encoding. |
| `client::focus_message` -> daemon `focus` action | Client-forwarded routing values reach `mon.focus(...)`, which shells out to tmux and wmctrl. |
| `std::io::Error` -> error context | Platform error messages can embed the socket path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-02 | Denial of Service | `client::read_framed` | high | mitigate | `MAX_RESPONSE_BYTES` checked against the accumulated length after every read; accumulator never pre-sized to the cap. Both sides of the boundary are tested (exactly-cap accepted, cap+1 rejected). |
| T-11-03 | Denial of Service | `client::read_framed` | high | mitigate | Whole-operation `Instant` deadline checked before every read, plus a per-read `set_read_timeout` sized to the remaining budget. Proven by the one-byte-per-100ms dribbling-peer test returning `snapshot.timeout` within its deadline. |
| T-11-04 | Denial of Service | JSON deserialization | medium | mitigate | `serde_json`'s built-in 128-level recursion limit returns an error rather than overflowing the stack; a 512-level fixture test proves the process survives. No hand-rolled depth guard. |
| T-11-05 | Information Disclosure | io error -> `SnapshotFailure` / `FocusFailure` | high | mitigate | Every `io::Error` is discarded at the `map_err` site and replaced by a fieldless `TransportOp`. The socket path, which appears in some platform messages, cannot reach a failure value because `src/error.rs` has no owned-string field. |
| T-11-06 | Elevation of Privilege | `focus_message` -> daemon shell-out | medium | mitigate | Routing values are type-validated and capped at `MAX_ROUTE_BYTES` bytes before a `FocusTarget` can exist; the message is built through `serde_json` so a value containing a quote or backslash is escaped rather than able to inject a key. The daemon performs its own all-strings check as defence in depth. |
| T-11-12 | Tampering | framing | medium | mitigate | A second framed object arriving in the same read is rejected as `snapshot.framing` with reason `trailing_content` rather than silently ignored, so a response-splitting attempt is a visible failure. |
